Illustrative lifecycle of a removable learning event
01
Resolve the target event

Identify the event key, tenant scope and the evidence associated with the learning.

02
Find dependent events

Walk read/write or decision-dependency links to identify state that could have been influenced.

03
Rebuild and verify

Reconstruct from the retained event history and compare against expected state and invariants.

Important distinction
Event deletion is not automatically model unlearning

The UI demonstrates a reversible application-state ledger. Exact removal inside DOTS's sparse neural memory depends on frozen addressing, logged read/write sets, deterministic execution and dependency-aware replay. A production implementation must prove the relevant conditions for its model and workload.

Evaluation principles
Evidence before claims

Use deterministic fixtures, hold-out cases, fixed seeds, explicit success criteria and repeated runs. Compare not only issue resolution but also LLM call count, latency, localized state changes, reviewer acceptance and removal correctness.

Publish the dataset generator and raw results alongside the demo. If simpler rules perform as well, keep the simpler implementation.
