Executive product briefing · V1

Knowledge that can adapt, explain and recover.

Living Knowledge Mesh connects facts and evidence, updates only the relevant parts of the network, and keeps a record of changes. The business goal is safer, cheaper, more auditable AI-assisted operations, not another giant model.

LOCAL-FIRST · SPARSE BY DESIGN

Keep the knowledge connected.
Keep decisions under control.

Think of it as a living map of business facts. When a new signal arrives, the mesh finds the affected neighborhood, updates a small set of states, and records how those states changed. Human approval and optional model reasoning sit around that core.

How a decision moves

Every layer has a specific job.

01
Find the affected neighborhood

Match a signal against known facts and connected evidence instead of re-processing the entire knowledge base.

02
Update locally, write sparsely

A shared cell-transition rule propagates state through nearby nodes. Only material state changes enter the journal.

03
Keep a route back

Each journal event records before and after values, allowing a correction to be inspected or reversed in the demo.

Sparse memory · provenance · rollback

Remember the change, not the whole world.

The journal records material state changes with before/after values and a link to the prior event digest. Reversals append a compensating event instead of deleting history. Current storage is this browser only, not a shared or tamper-proof production ledger.

Recommended role for Laya
Current model policy selection.
Not connected

Evaluate Laya for typed questions such as “is this record in conflict?” or “which category applies?”. It is a decision model, not a chat LLM. Its checkpoint and runtime must be measured before promising a one-gigabyte ceiling.

⚠
Deployment constraint

Vercel serves the lightweight application and thin adapters. Do not package a hundreds-of-megabytes model in a serverless function bundle. Run quantized inference in a tested local/browser runtime or separate inference process; send data to a hosted API only with approval.

File sizes are published model artifact sizes, not measured peak RAM. Chosen model is stored in local UI state only; it does not trigger a download or request.
Business outcomes · evaluation plan

Prove the operating gain, not a benchmark headline.

The mesh matters only if it improves decision quality, lowers repeated work or reduces model inference. The measures below are proposed targets, not achieved results.

Efficiency
↓ Rework

Repeated correction rate

Measure how often the same fact is flagged and fixed again before and after approved feedback enters memory.

Quality
↑ Evidence

Grounded decision rate

Audit a fixed test set and measure whether each action is supported by source facts and correct provenance.

Cost
↓ Tokens

Inference per resolved case

Compare full-context LLM calls with local retrieval, sparse propagation and selective model escalation.

Evaluation protocol
A fair comparison against simple baselines before ROI claims.
TO BE MEASURED
1
Build a fixed labelled dataset

Use representative, permissioned cases and label the expected outcome, evidence and acceptable uncertainty.

2
Compare three baselines

Rules only; an LLM with retrieved evidence; and a hybrid mesh with sparse local updates and selective inference.

3
Publish quality, cost and resource use together

Track precision/recall, calibration, rollback correctness, p50/p95 latency, peak resident memory and model bytes downloaded.

4
Release after repeatable results

Pin dataset and versions, publish raw results, document failure cases and remove illustrative figures from the CEO view.

This build does not claim ROI, accuracy, speed or memory reduction. Metrics must come from reproducible tests on the target workload and hardware.
System architecture · low-memory by design

Keep the always-on core small and reversible.

Separate cheap graph operations from optional reasoning. The web host delivers the UI; local processing handles neighborhood updates; inference is selected independently to fit deployment and privacy constraints.
